The Chat with Work Local Agent now comes with a desktop app, and you can chat with Chat with Work from your computer: in the app's window, drawn as the web draws it, or in the terminal UI. Shared folders can also let the assistant change files, when you turn that on for a folder, with every change approved by you and old versions kept in your system trash.

**Download:** the desktop app for macOS (`cww-app-v0.2.0-macos-universal.dmg`, signed and notarized), Windows (`cww-app-v0.2.0-x86_64-pc-windows-msvc.zip`, or `aarch64` on Arm) and Linux (`cww-app-v0.2.0-x86_64-unknown-linux-gnu.tar.gz`, or `aarch64`), each with `cww` inside; or `brew install --cask crmne/tap/cww-app`. `cww` alone installs as before: Homebrew (`brew install crmne/tap/cww`), WinGet, the MSI or `.pkg`, `.deb` and `.rpm`, the AUR, Nix, or the one-line installers. See the README for each.

![The desktop app's chat page](https://github.com/crmne/chatwithwork-local-agent/releases/download/v0.2.0/desktop-chat.png)

## New

- **A desktop app.** A menu bar item on macOS, a notification-area icon on Windows and a tray item on Linux show whether Chat with Work can reach this computer, and pause or resume sharing. Its window pairs the computer, shares folders with the system folder picker, shows the deny list and the activity log, and starts the app at login. On first run it starts the agent, pairs, and offers to share your Documents folder, sharing nothing until you say so. It uses no CPU while idle. By @crmne in #1.
- **Your chats in the desktop app, as the web shows them.** The sidebar with New chat, search, Recent and Pinned stays current as chats start, change or go, on the web too. Answers stream in with their sources, tool work folds into one live line, and the services' and models' logos and file-type icons come from Chat with Work. Pick the model, attach files (or drop them on the window), approve or deny a change, answer a connected service's questions, and retry, branch, share, rename or delete a chat.

  ![A change to approve in the desktop app](https://github.com/crmne/chatwithwork-local-agent/releases/download/v0.2.0/desktop-approval-dark.png)

- **Chats in the terminal UI.** `cww` now opens on your chats, laid out like the app: the chat list on the left, the conversation and the composer on the right, and a single word at the top right when something needs you. The composer works as Claude Code's does, with `/` commands (`/new`, `/resume`, `/model`, `/attach`, `/retry`, `/branch`, `/share-chat` and more), earlier questions on `↑`, and approvals and questions answered from the keyboard. The mouse works too, and the settings (shared folders, the deny list, activity, account, general) are a page away with `,`. By @crmne in #2.

  ![Approving a change in the terminal UI](https://github.com/crmne/chatwithwork-local-agent/releases/download/v0.2.0/tui-chat-approval.png)

- **Let the assistant change files in folders you choose.** Turn on "Allow changes" for a shared folder, on your computer only (the switch in the app, `w` in the terminal UI, or `cww roots allow-changes`), and the assistant can create, edit, move and delete files there, and create Word documents and Excel workbooks. Chat with Work asks you before each change and shows what it will do. Every replaced version and every deleted file goes to your system trash, and every change is in the local activity log. Changes have their own limits (30 a minute, 500 a day, 50 MB written an hour), and folders stay read-only unless you turn it on. No programs, scripts that run when opened, shortcuts or macro documents are ever written, and secrets, your home folder's dot files, Git internals, shell startup files, autostart entries and editor settings are never changed. Tested through the real daemon on Linux, Windows 11 and macOS 27, as a background service too.

  ![Allowing changes in a shared folder](https://github.com/crmne/chatwithwork-local-agent/releases/download/v0.2.0/allow-changes.png)

- **Works behind an HTTP proxy.** Set `proxy` in `config.toml`, or let `cww` read `https_proxy` and `no_proxy` as curl does. TLS still runs end to end to Chat with Work, and `cww status` shows the proxy in use.
- **`cww login` starts the daemon** after pairing, so a new computer is connected in one step (`--no-daemon` skips it).

## Fixed

- **The Linux daemon connects on systems with systemd-resolved or NetworkManager.** There `/etc/resolv.conf` points into `/run`, which the 0.1.0 sandbox didn't let the daemon read, so it couldn't resolve any name and never connected.
- **The deny list matches names the way case-insensitive filesystems do.** On macOS and Windows, a name written with look-alike Unicode letters (such as `.Kube` with a Kelvin sign) could reach a denied folder; names are now compared in full Unicode case folding.
- **The activity log can't be forged through a file name.** Paths with control characters, direction marks or line separators are refused, and `cww log` shows any such character escaped.
- **Folder changes made at the same time are all kept.** Adding, removing or renaming folders and pausing at once could drop one of the changes from `config.toml`.

## Known limitations

- **Changing files needs Chat with Work's support for it** on the server you're paired with; until then, folders that allow changes are shared read-only.
- **Allowing changes trusts Chat with Work's approvals.** The approval happens on the server, and the daemon can't tell a real approval from a forged one, so a compromised server could change files in folders where you allow changes without asking you. Everything replaced or deleted is still in your trash, within the limits, and in the local log. Allow changes only in folders you could restore, and `cww pause` stops everything at once. The README's threat model has the details.
- **The Windows builds aren't signed yet,** the app and `cww` alike, so SmartScreen says "Windows protected your PC" when you open a downloaded one: choose **More info**, then **Run anyway**. Extract the app's zip to a folder you'll keep, since the daemon's logon task points at `cww-agent.exe` in it.
- **The macOS `.pkg` isn't signed yet,** so Gatekeeper won't open it with a double-click. The app's disk image, Homebrew and the one-line installer are signed and notarized.
- **On Linux the app comes as an archive,** not in the `.deb`, `.rpm` or AUR packages. It needs glibc 2.35 or newer (Ubuntu 22.04, Debian 12, Fedora 36 or later) and a tray that shows StatusNotifierItems (Waybar, KDE, or GNOME with the AppIndicator extension); without one, closing the window quits the app.
- **The app doesn't update itself yet.** Download the next release, or `brew upgrade --cask cww-app`.
- **A few things still happen on the web:** pinning chats or moving them to a project, and downloading files sent with a question. A new chat in the app or the terminal doesn't show the services it can reach or suggested questions.
